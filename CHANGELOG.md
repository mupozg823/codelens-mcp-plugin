## [Unreleased]

### Changed

- **analysis-lite's cold first call is about a third faster on bundled code** — after #471 a cold call on the winnation working tree still spent most of its time in tree-sitter, not OXC (sampled: 762 samples in OXC semantic vs about 70,000 in tree-sitter work). Two causes. Each JS/TS call site found its enclosing declaration by walking `Node::parent`, which re-descends from the root, so the cost grew with depth squared per call: 349 ms of a 545 ms call extraction on one 2.4 MB bundle, and 25.8 s for 250 nested callbacks in a debug build. Callers are now assigned in one walk of the tree with an ancestor stack, using the same decision rules. And every file was parsed by tree-sitter twice, once for module tokens and once for call sites; the two passes now share one parse when they use the same grammar (`.js`, `.mjs`, `.cjs`, `.ts`, `.mts`, `.cts`, `.tsx`; `.jsx` keeps two parses because its calls use the TSX grammar), and an in-scope file's call sites are filled together with its analysis. On winnation the cold first refs call went from 26.8/27.1 s to 15.4/18.9 s (two interleaved rounds, load average about 55); later calls read both caches and are unchanged within noise. Results are byte-identical to #471 on winnation (5 calls) and to the earlier installed build on stream-admin (5 calls); on the 2.4 MB bundle all 27,120 call sites, and all 205 in `components/OverlayRenderer.tsx`, get the same caller as the parent walk. Tests: the parent walk is kept as a test oracle over methods, fields, static blocks, pairs, assignments, declarators and IIFEs in `.js`/`.ts`/`.tsx`; 250 nested callbacks must finish under 3 s (old: 25.8 s); one shared parse per file and identical analysis and call sites for each extension.

- **analysis-lite no longer stalls on large bundled files** — two lookups were quadratic in file size. Every declaration and reference got its line by counting bytes from the start of the file (`offset_to_line_col`), and every call site found its binding by walking every reference of every declaration (`binding_at`), on every query because call evidence is not cached. On the winnation working tree (3,393 JS/TS files, 77 of them untracked 2.4 MB bundles under `.omo/evidence/`), the installed build's first refs call gave no answer within 300 s; benchmarks never saw it because they ran on `git archive` snapshots without untracked files. Lines now come from a per-file table of line starts (binary search) and bindings from a span → declaration map built once per analysis. The same session now answers in 22.7 s for the cold first call and 4.3–5.5 s afterwards (refs and impact, 5 calls, loaded machine), and results are byte-identical to the build with only the line fix; on stream-admin (964 files, no large files) 5 calls are byte-identical to the installed build and take 0.5–1.0 s instead of 0.9–1.6 s. Two tests fail on the old code with an assertion (60,000 references took 22.9 s, 60,000 binding lookups 24.2 s) and a third checks the line table against the old byte scan at every offset, including CRLF and multi-byte text. The winnation session still holds 1.8–2.3 GB while the bundles' parses are cached; the audit (`docs/architecture-audit-2026-10-29.md`) lists that and the remaining warm cost as next steps.

- **analysis-lite resolves CommonJS `require`** — imports and exports came only from OXC's module record, which is ESM-only, so a `.cjs` module's users in other files were never linked: in shadow-partner, `laneKey` in `scripts/browserctl/worker.cjs` and `scripts/chromeext/relay-worker.cjs` listed only its own file. Top-level `module.exports = { X, Y: local }`, `module.exports.X = local` and `exports.X = local` are now named exports (respecting a reassigned `module.exports`), and `const { X, Y: Z } = require("<literal>")` and `const m = require("<literal>"); m.X` resolve to them through the existing module resolver, with resolution `verified_cjs_require_export_identity`; each binding is checked with OXC (a locally declared `require` or `module`, a shadowing parameter or a reassigned binding is not linked). On a shadow-partner snapshot, 6 targets × refs/impact lost no row; `laneKey` gained its calls in `tests/browserctl_lanes.test.cjs`: in `worker.cjs` 3 calls on 3 lines, refs 2 → 5 and impact 3 → 6 edges; in `relay-worker.cjs` 5 calls on 3 lines, refs 2 → 7 and impact 3 → 8 edges (every call `rg -w` finds there). `BrowserController`, `PAGE` and `evalSource` are unchanged: their test files call `BrowserController.create()` or `new BrowserController()`, read `PAGE[name]`, or load the module with `require(path.join(...))`, none of which is a row yet. Three winnation targets × refs/impact are identical. `docs/operations/analysis-lite.md` lists the forms read and not read.

- **analysis-lite binds an absolute target to its checkout, not the nearest `package.json`** — the per-call root came from the nearest root marker above the file, and `package.json` sits nearer than `.git`. In shadow-partner (a Python repository) the browser controller `scripts/browserctl/worker.cjs` has its own `package.json`, so a refs call on `BrowserController` bound `scripts/browserctl`, read 1 file and had the 11 test files at the repository root that use it out of scope; bound to the checkout, the call reads all 57 JS files (those tests reach it through CommonJS `require`, which analysis-lite does not resolve yet, so their rows are still missing). It also broke the rule that a relative and an absolute spelling of one file bind one project: from a session launched in the repository, `scripts/browserctl/worker.cjs` bound the checkout and its absolute path bound the package. The root is now the launch root when it holds the file, else the enclosing git checkout when that checkout's discovery walks the file (gitignore and excluded directories, the same `GitignoreFilter` the watcher uses), else the nearest marker as before — so a gitignored scratch folder with its own marker keeps it. Three startup tests pin the cases; removing each of the three rules fails its test.

- **analysis-lite counts `next/dynamic` imports as references** — `dynamic(() => import("@/components/X").then((mod) => mod.X))` used the export only through a member of the callback parameter, and analysis-lite never read it, so refs and impact for a lazily loaded component missed the file that loads it. On winnation, `components/OverlayRenderer.tsx` loads 60 components this way and `BjGaugeOverlay` refs listed 8 files without it. A `.then` callback with one identifier parameter whose member is read through that parameter's own binding (OXC semantic, so a shadowing inner `mod` is not counted) now resolves to the export like a static import, with resolution `verified_esm_dynamic_import_export_identity`, and its caller is the enclosing declaration, so impact continues from the lazy binding. On 18 winnation targets × refs/impact, no previous row changed or disappeared; 28 rows were added, for the 5 targets loaded this way, e.g. `BjGaugeOverlay` refs 12 → 13 and impact 14 → 17 edges, and `CreatorDonationsWorkspace` impact +11 edges through `CreatorWorkspaceLazy.tsx` into `renderCreatorWorkspace` and its tests. Destructured parameters, `await import()` destructuring and default-export `lazy()` remain unread (`docs/operations/analysis-lite.md`).

- **A cold full index writes less** — every symbol and import INSERT fires the FTS triggers, so SQLite opens a statement journal for it, and past 64 KiB that journal became a temp file: a cold `refresh_symbol_index` spent about 1,540 of its 1,696 `pwrite` samples re-writing that file. The symbol index connection now sets `temp_store = MEMORY`. On winnation (3,101 files, 58,409 symbols, fresh snapshot each run), a cold full index went from 4.86 s to 3.40 s (median of six alternating runs each) and a cold analysis-lite session's first refs call from about 7.1 s to 5.3 s (three runs each); peak footprint is unchanged (139–148 MB), and the `files`, `symbols`, `calls`, `imports` and FTS tables are identical row for row. The embedding store is unchanged: its indexing showed 3 `pwrite` samples in 15 s.

- **Embedding pads less** — a 128-text embedding batch went to the model as one call padded to its longest text; on the self corpus that was about 1.4x the real tokens. Each batch is now sorted by length and embedded 32 texts per call (`CODELENS_EMBED_SUB_BATCH`, `0` = previous behaviour), with vectors returned in input order. First full index of 13,799 symbols: 102.6/94.4 s → 84.2/90.0 s (two fresh-snapshot runs each). Quality was neutral: `get_ranked_context` MRR 0.773 → 0.778 (self) and 0.417 → 0.426 (gin); `semantic_search` 0.701 → 0.701 (self) and 0.289 → 0.272 (gin, one query). The bundled model quantizes activations per call, so vectors change slightly; existing indexes keep theirs until re-embedded.

- **analysis-lite gives memory back** — parallel parsing (#460) raised an analysis-lite stdio server's footprint on a 3,058-file project from 292 MB to 676 MB after three queries, and it never came down: mimalloc keeps a heap per thread, blocks the request thread frees after a rayon worker allocated them wait on that parked worker's delayed-free list, and the parse caches lived for the whole session. After every query the server now collects on the request thread and every rayon worker (434 MB in use), and the idle sweep empties the parse caches once no query has used them for `CODELENS_ANALYSIS_LITE_IDLE_SECS` (default 600), which brought the idle server to 45 MB. Query results and latency are unchanged (28/28 identical, median 1.0 s).

- **analysis-lite rows carry their code line, and stop repeating identities** — a pilot comparing reference output shapes saw follow-up file reads fall from 15.2 to 3.2 per task when each location came with its source lines, and analysis-lite rows had none. Every reference row and impact edge now carries `location.line_text` (trimmed, capped at 160 bytes, from the snapshot the query read). To pay for it, the wire form drops what each row repeated: a refs row's `target` (always the response `target`), impact edge endpoints equal to a `results.nodes` entry (written as its `symbol_id`), and per-row `source_hash` (hoisted to `snapshot.source_hashes` when a file has one hash). On the 14-target winnation set, refs payloads shrank 6% with a line on all 66 rows, impact returned 152 edges instead of 132 under the same 18,000-byte bound, and clipped calls fell from 9 to 7; row contents are otherwise unchanged. `docs/operations/analysis-lite.md` adds a Codex `output_token_limit` snippet: Codex's fallback budget for a model outside its catalog is 10,000 bytes.

- **analysis-lite refs and impact answer in about a second, and a default call no longer fails on size** — every call re-read up to 2,000 JS/TS files and ran OXC analysis and tree-sitter call extraction on one thread, so on winnation (3,058 JS/TS files) a refs call took 6.9 s at the median and the same query again 7–11 s. Files are now read and analyzed in parallel and folded in path order; a file's OXC declarations and call sites are reused within the process while its content hash is unchanged (an edit is a miss); module resolution is memoized per build. Over 14 seeded targets × refs/impact the evidence is identical to the previous build apart from `snapshot.generation`; 28 calls went from 206 s to 30 s, median 6.9 s → 1.0 s, on a loaded machine. Evidence above the 18,000-byte wire bound is clipped by whole trailing rows (unresolved examples first, then references, or impact edges with the nodes only they reached) and `truncation.wire_bound` records the limit, the unclipped size and every omitted count; if not one row fits, the call is still rejected with `response_size_limit`. Default-argument calls on those targets went from 4 failures to 0 (9 clipped, all marked). The default `max_files` is 10,000 (was 2,000, which cut winnation and dropped test-file references, e.g. `vsStartReason` 0 → 5).

- **Security: stdio drops client-supplied `_session_*` keys, for every profile** — dispatch binds `_session_project_path` before a tool runs, and the stdio transport passed these root keys through from the client, so a `tools/call` carrying a forged `_session_project_path` bound an arbitrary directory and created `.codelens` index state in it. `serve_stdio` now strips `_session_*` from `tools/call` arguments and from `tools/list` and `resources/read` params, as the HTTP transport already did. This changes behaviour for every stdio client, not just analysis-lite: a stdio client that relied on sending these keys loses that binding (no known client sends them).

- **The tool description and the generated routing block no longer tell agents to bind first** — after the bound-session `instructions` shipped (#438), a 120-run reference A/B still saw 40 of 151 CodeLens calls go to `prepare_harness_session` on sessions the URL had already bound. Two other texts drove them: the tool description ("pass project=… on first use to bind") and the generated `CODELENS_HOST_ROUTING` invariant ("Bind once with prepare_harness_session"). Both now say that a host sending its launch directory has already bound the session and that `prepare_harness_session` is for a `project_binding` hint or a switch. `CLAUDE.md`, `AGENTS.md` and `.cursor/rules/codelens-routing.mdc` are re-synced from `codelens-mcp attach`, and `doctor` reports each as an exact match.

- **A session bound at `initialize` is no longer told to bind first** — the server's `instructions` always opened with "FIRST CALL of every session: prepare_harness_session", even when the host had already bound the session through `x-codelens-project`, the `?project=` URL query or an initialize `project` param. In an evaluation run, 28 of 213 CodeLens calls were such redundant `prepare_harness_session` calls; in 14 days of local sessions, 56 of 208 sessions that touched CodeLens called only binding and config tools. A bound `initialize` now gets instructions that name the bound root and reserve `prepare_harness_session` for switching projects. Unbound sessions (no binding, `$HOME`, unmarked or unknown paths) keep the bind-first instructions, which now also mention the URL query.

- **The daemon installer refuses unmarked project roots by default** — `install-http-daemons-launchd.sh` now writes `CODELENS_ALLOW_MARKERLESS_ROOT=0` (`--markerless-root deny`, or `allow` for the old behaviour). With hosts sending `x-codelens-project: ${PWD}`, a session launched in a folder with no root marker (for example `~/Downloads`) would otherwise have the shared daemon index that whole folder; it now falls back to the daemon's project.

- **Sessions survive a daemon restart** — session state lived only in daemon memory, so every redeploy (and every 30-minute idle expiry) left resurrected sessions unbound, reading the daemon's default project until they called prepare again, and without their client name. Soft state (chosen project binding, client identity, profile) is now journaled per session id under the runtime directory and restored on resurrection; trust is never stored. This replaces the in-memory identity cache added earlier in this release. `prepare_harness_session` without `project` in a session that chose its project now re-prepares that project and answers `building` within the budget instead of an error.

- **Daemon redeploys can keep macOS folder consent** — the deploy scripts sign ad hoc, which macOS keys to the content hash, so after every redeploy the first file open in `~/Downloads`/`~/Documents`/`~/Desktop` waited on a consent dialog (234.8 s and over ten minutes on 2026-10-10). With `CODELENS_CODESIGN_IDENTITY` set to a keychain code-signing identity, `redeploy-daemons.sh` and `install-http-daemons-launchd.sh` sign with it and a fixed identifier, so one consent survives rebuilds; a missing identity aborts before the binary is replaced. `redeploy-daemons.sh` now signs a staging copy and swaps it in, so a signing failure leaves the running daemon's binary untouched. Without the variable, behaviour is unchanged apart from a notice.

- **Stale-daemon and stale-SCIP signals say how bad and what to run** (revived #310, #306) — the drift payload carries `severity` and a `workaround_command` matched to the cause (restart by the daemon's own launchd label when the binary changed on disk; `redeploy-daemons.sh`/`redeploy-dev-daemon.sh` when the checkout is ahead). `scip_index_stale_warning` adds `max_stale_age_secs`, `precise_threshold_secs` (`CODELENS_SCIP_PRECISE_MAX_STALE_SECS`, default 24 h) and `severely_stale`, so a one-second lag and an eleven-day one no longer look alike.

- **Binding answers within a budget** — a project's runtime is built on a background thread and a request waits at most `CODELENS_BIND_BUDGET_SECS` (default 20); then `prepare_harness_session` returns `activated: false, binding_status: "building"` (the session is bound to the project) and project tools return the retryable `index_not_ready`, while the build continues and the next request installs it. On 2026-10-10 an index open in `~/Downloads` waited 234.8 s on the macOS consent dialog a freshly re-signed daemon gets for that folder, past Claude Code's 60 s cutoff. Replaces the 120 s follower wait; `index_not_ready` is now retryable.

- **Linked worktrees inside a project are not indexed** — after the `.gitignore` cleanup, SignatureStudio still held 3,354 of its 5,124 indexed files under `.codex-worktrees/<name>`, linked worktrees that duplicate the tree. A directory below the root whose `.git` file points into `.git/worktrees/` is skipped by the walk and the watcher; submodules (`.git/modules/`) stay. The discovery signature becomes `gitignore=on;nested-worktrees=off`, so each index gets one cleanup refresh on its next bind.

- **Discovery honors `.gitignore`** — across 23 locally indexed git projects 16.9% of indexed files (6,913 of 40,825) were gitignored, one repository 64% (archived production snapshots and a build-output `public/`); every copy re-declared the same symbols, so a path-less `refs` lookup saw `renderBoard` declared in 53 files and refused to guess. The walk now uses the `ignore` crate (`.gitignore` at every level, `.git/info/exclude`, parent ignore files; only inside a git checkout; hidden directories kept; global excludes left out), the watcher applies the same rule per path, and `meta.discovery_signature` makes the first bind under the new rule run one `refresh_all` that deletes the stale rows without re-parsing unchanged files. `CODELENS_INDEX_GITIGNORE=0` restores the old walk.
- **TS/JS files are served by TypeScript 7's own server when no `tsserver.js` exists** — with the global `typescript` at 7.0.2 and no workspace copy, typescript-language-server could not start, so every TS/JS diagnose/navigation/rename failed at `initialize` (59/59 `.js` and 36/38 `.mjs` diagnose calls in two weeks; the builder's diagnose gate failed 17 of 19 times). A `tsc --lsp --stdio` recipe is chosen per project by mirroring typescript-language-server's own lookup; an older `tsc` is never launched as a server.
- **Failed calls record `error_kind` in the usage log** — a stable label per error variant; the message is not recorded because it can carry symbol names, queries and paths.

- **Binding a fresh git worktree seeds its index from a sibling checkout** — first binds to new `.claude/worktrees/*` / `.codex/worktrees/*` roots parsed the whole tree inside the MCP request (`prepare_harness_session` p90 18.9 s, p99 208 s, 16 client timeouts in two weeks). The freshest index among the main checkout and the other linked worktrees (same subpath) is copied with `VACUUM INTO`, reading only the on-disk git layout; any failure falls back to a full build. One-shot on a 2.8k-file repo: 18.2 s → 3.4 s.
- **`refresh_all` skips unchanged files before parsing** — it read, hashed and parsed every candidate and discarded unchanged ones at commit time; files are now compared with their indexed `(mtime, hash)` first, and a content match with a moved mtime is only re-stamped (`retime_file`).
- **`symbols.parent_id` is indexed (schema v7)** — a self-referencing foreign key with `foreign_keys=ON` made every symbol delete scan the table. Deleting 27k symbols: 53.9 s → 0.13 s; re-binding a worktree 1.2k changed files away from its seed: 124 s → 7.1 s (the live 402 s bind).
- **`stats()` answers freshness from `stat`** — same rule (equal mtime and hash), but a moved mtime is stale without reading and an unchanged mtime + size indexed more than 2 s after the write is fresh without reading (racy-clean). `get_current_config` on a 3.1k-file repo: 549 → 87 ms.
- **Resolved call graphs are cached per scope and extracted in parallel** — every callers/callees query rebuilt the graph by parsing the whole scope on one thread (`graph(mode=callers)` p50 8.1 s). Snapshots live in the project `GraphCache` under the generation the watcher and refreshes already invalidate; first query 13.5 → 3.8 s, repeat 13.7 s → 1 ms, identical results.
- **Scoped references parse only files that mention the name, in parallel** — 1.3–2.7 s → 42–213 ms with byte-identical reference lists; `review(mode=changes)` on two files 25–48 s → 6–21 s.
- **Dead-code pass 2 reuses the index instead of re-parsing every file** — it read each candidate file twice and parsed it again with tree-sitter to list the functions to judge (47% of the pass on tuanbo), then parsed every Rust file once more for `#[cfg(test)]` regions. Each file is now read once; a file whose indexed content hash still matches takes its functions from the stored call edges (the same extractor wrote them), an edited one is re-parsed, and the test-region parse and line split run only for a file that has an unreferenced name. Token counts are keyed by NFC like the stored names, so an NFD spelling counts as a use. Warm `dead_code_report` against main 53d74e3b, median of 5 uncached runs on fresh clones, identical finding lists: tuanbo-broadcast-suite 3.01 → 0.44 s and winnation 1.85 → 0.30 s (TypeScript, so this change alone); with the one-shot fix below, codelens-mcp-plugin 1.59 → 0.29 s, shadow-partner 0.93 → 0.17 s, greybox 0.52 → 0.07 s.
- **Suggestions target only callable tools** — deprecated tools are dropped, an unlisted fine-grained tool becomes its listed facade with the `mode` added to the pre-filled call (`bm25_symbol_search` → `search` + `mode: "bm25"`), anything else is dropped. Before, 55 of 3,345 suggestions were followed within three calls, several naming deprecated or unlisted tools.

- **BM25-F sparse lane splits camelCase identifiers; one identifier splitter instead of four (K-0030)** — the sparse-lane tokenizer lowercased before splitting, so `SparseSymbolIndex` or `objectContaining` stayed one opaque token and only snake_case names matched their words. It now reads case boundaries first and emits the compound plus its parts. The embedding prompt, query-intent analysis and this tokenizer share `codelens_engine::unicode::identifier_words`; embedding input is byte-identical on 10,080 real identifiers (no re-embed). Measured with `benchmarks/embedding-quality.py` on three corpora (before 7bd7674e, after aadf5818 plus this change): `bm25_symbol_search` MRR@10 gson 0.079 → 0.283 and jest 0.060 → 0.122, hybrid `get_ranked_context` MRR up on all three (self 0.740 → 0.744, gson 0.468 → 0.499, jest 0.188 → 0.258). gson and jest are small (30 and 24 queries). Self `bm25_symbol_search` is a measured null (0.6538 → 0.6512; one query lost rank 1, one gained recall), which misses the acceptance rule fixed before measuring (improve on self and one external corpus); the record states why it landed anyway and self candidate-missing rate went 0.054 → 0.063, still inside every CI floor. The cost is exact-identifier precision: a single-word query such as `Resolver` now ties with compound names that contain it (jest `Resolver` rank 9 → out, `Runtime` 1 → 4). The SQLite `symbols_fts` tokenizer is unchanged and still does not split camelCase. Record: `docs/research/surface-retrieval-cycle-2026-09-17.md` §4.3.
- **Preset membership is generated from `tools.toml` (ADR-0013 decision 5, K-0023)** — `presets.rs` carried five hand-written membership arrays (154 entries, 80 distinct names) beside each tool's `preset_tags`, and `regen-tool-defs.py` only checked that the two copies agreed, so every surface change was made twice. The generator now inverts `preset_tags` into `MINIMAL_TOOLS`, `BALANCED_EXCLUDES`, `PLANNER_READONLY_TOOLS`, `BUILDER_MINIMAL_TOOLS` and `REVIEWER_GRAPH_TOOLS` in `metadata_generated.rs`; `presets.rs` keeps only the aliases and the per-surface rationale. The four pending-D3 symbolic edit tools, which have no `[[tool]]` table to carry tags, sit in a top-level `[dispatch_only_preset_members]` table that the generator restricts to the pending-D3 allowlist. Generated membership and order matched the hand arrays exactly before the swap.
- **Always-load slice aligned to ADR-0016 (core-10)** — `tool_anthropic_always_load` had grown to 35 preloaded tools: the ADR's ten plus 25 fine-grained duplicates kept "round-trip-free" under #365. Every Claude Code session therefore paid roughly 26 KB of context after `prepare_harness_session` (measured 2026-09-16 on the live daemon: 14 tools / 12.6 KB listed before binding, 63 tools / 35 preloaded / 44 KB of model-facing schema after) for capability the `search` / `graph` / `review` / `overview` / `diagnose` facades already cover. The preloaded set is now exactly `CORE_10_TOOLS` (10.8 KB); everything else stays discoverable through the host's tool search via `anthropic/searchHint`, so a direct fine-grained call costs one search round trip instead of a permanent context tax. `ALWAYS_LOAD_SCHEMA_BUDGET_BYTES` ratchets 28 KiB → 12 KiB and `always_load_surface_matches_adr_0016_core` pins the membership to the ADR text.
- **`tools/list` rows are no longer persisted to the usage log** — listing traffic is a host cache refresh, not a tool call, yet it made up 88% of `.codelens/telemetry/tool_usage.jsonl` (40,213 of 45,731 rows on 2026-09-16): long-lived MCP clients re-list on a timer (a Python-SDK client polled every 180 s for three weeks inside one session). Neither the deprecation removal gate nor the surface ratchet reads those rows. In-memory metrics still count every listing; only the JSONL boundary filters (`persist_event_to_usage_log`).
- **`CLAUDE.md` always-on surface cut from 17.2 KB to 7.7 KB** (7.2 KB before the regenerated routing block gained its host-facts section) — the symbol-query seam description, the feature-flag matrix, the CI command mirror, and the mutation-gate / harness-mode quick reference moved verbatim to `docs/design/symbol-query-seam.md`, `docs/operations/build-features.md`, and `docs/operations/mutation-gate.md`. The generated `CODELENS_HOST_ROUTING` block is untouched; the hand-written part now carries only the architecture invariants, the short verify recipe, and the pitfalls list.

### Fixed

- **Semantic lookups on an unindexed project fail instead of reporting nothing (K-0061)** — with an empty embedding index, `find_code_duplicates` and `find_misplaced_code` answered success with zero results, so a project nobody had indexed read as "no duplicates" (winnation `review(mode=dupes)`: `count: 0`, confidence 0.8); `find_similar_code` and `classify_symbol` failed with "Symbol 'X' not found in index", which blames the symbol. All four now fail with `feature_unavailable` and "Embedding index is empty. Call index_embeddings first", the check `semantic_search` already had; one helper serves all five.
- **A clipped text-channel array says how many items it dropped (K-0062)** — the text summarizer cuts every array to three items and only marked `truncated: true`, so `count: 80` beside three `duplicates` read as a contradiction with no size to recover. It now leaves the same `<key>_omitted_count` the structured summarizer leaves (`duplicates_omitted_count: 77`). The token budget was not the cause: the clipped response used 13% of it.
- **One-shot `index_embeddings` builds the index (K-0060)** — `--cmd index_embeddings` queued a background job and exited, so the job never ran and the index stayed empty. One-shot and `--batch` now run it in the foreground unless `background: true` is passed.
- **One-shot CLI calls no longer start a file watcher or pre-warm language servers** — `--cmd` and `--batch` built the same runtime as a server, so each call started a watcher and, on Rust and Python projects, spawned rust-analyzer or a Python server only to shut it down at exit (up to 250 ms each). The watcher had seen no change, yet the freshness hint answered `basis: "watcher_running"`; one-shot responses now report the index age, as the hint's own documentation said they did. `dead_code_report` median of 5 runs: codelens-mcp-plugin 0.35 → 0.29 s, shadow-partner 0.26 → 0.19 s, greybox 0.12 → 0.09 s; TypeScript projects with no server to pre-warm are unchanged.
- **Dead-code and cycle reports hold up on projects they were not tuned on** — a blind adjudication on three held-out projects (Python/Swift, an Electron/TS monorepo, Python+TS) found 0 of 42 sampled dead files really dead.
