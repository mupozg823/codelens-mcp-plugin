# Analysis-lite approved implementation and pilot

Approved 2026-10-26. Preserve existing profiles, legacy APIs, user model/effort,
global CodeLens-off settings, WIP and shared processes. One persistent SOL worker
owns bounded sequential dispatches in `codex/analysis-lite`; parent owns review,
integration and any requested external publication. No nested delegation, paid
fallback, global configuration edits, launchd, autostart or engine rewrite.

1. Repair benchmark accounting: inherit normal host configuration/authentication,
   record provider raw input/output/cache separately from server estimates, keep
   missing measurements unknown and separate process KPIs from task quality.
2. Freeze six tasks and independent gold before observing results: three everyday
   tasks (including real edits and acceptance tests), three hard tasks covering
   same-name declarations/reexports, local plus external use, bounded impact.
   Reuse existing research and actual large TypeScript projects including
   tuanbo-broadcast-suite/winnation; hash inputs, gold and acceptance criteria.
   Do not expose gold to evaluated agents or replace tasks after results.
3. Add typed JS/TS declaration-identity reference and bounded reverse-callgraph
   evidence using existing engine/runtime seams. Merge local/external results,
   deduplicate provenance, retain backend errors and truthful relation kinds.
   Unsupported imports/types/non-call references remain partial/unsupported.
4. Expose only `search(mode=refs)` and `graph(mode=impact)` on `analysis-lite`.
   Generate schema, validation and fingerprint from one contract; reject other
   modes, aliases and mutations even on direct calls. Preserve session/role/
   generation fences and response envelopes. Include target/snapshot/backend/
   provenance/status/unresolved/truncation/freshness/error evidence. Use one
   task-owned foreground HTTP process with canonical project binding per host
   session; different worktrees bind separately. Verify real Codex and Claude
   discovery and structured responses; CLI success does not prove Desktop.
5. Run relevant regression/unit/HTTP/codegen/fmt/clippy checks with one cargo
   build job and task-owned cache. Pilot at most 48 actual model runs:
   6 tasks × 2 arms × 2 repetitions × 2 hosts. Native baseline versus same host
   plus candidate and short optional project guidance; no forced use. Preserve
   current user model/effort, fresh conversations, equivalent isolated sources,
   seeded crossover order, cold/warm/setup timing, failures and raw usage.
   Unsupported, authentication, quota and timeout rows remain visible; no hidden
   extra model probes or synthetic gold substitutes.

Adoption is per host/language/task scope. Everyday tasks require zero quality
regressions and paired median wall time or actual tokens at least 15% lower,
without the other metric increasing. Hard tasks require one independent-gold
baseline failure/omission improved in both repetitions, zero critical regression
on baseline successes, and both token and wall ratios ≤1.25 for improved tasks.
Wrong declarations, errors converted to zero and incomplete analyses reported as
complete must all be zero. Missing actual usage is unknown/inconclusive. Report
pilot limitations and non-adoption honestly; never globally activate from results.

Deliver actual diffs/commits, command exit codes/logs, host raw responses, all run
manifests and usage, independent grader/statistics, activation decision and rerun
instructions. Progress and unresolved scope are in the operations ledger.
